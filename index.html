01

What is SAP RDP?

Start with the product boundary.

Key idea: SAP Responsible Design and Production is a cloud solution on SAP BTP. Treat it as a BTP application integrated with ERP—not as another ABAP module inside S/4HANA.

RDP supports sustainability processes such as Extended Producer Responsibility (EPR), packaging-related reporting, packaging taxes, and packaging-data analysis. From a security perspective, the important question is how human users, BTP authorization, application roles, and machine-to-machine integration fit together.

Identity

Who is the user?

Corporate IdP / SAP Cloud Identity Services establishes the user's identity.

Authorization

What may they do?

BTP role collections bundle RDP application roles for business personas.

Integration

How does data arrive?

S/4HANA, ECC, files, or APIs supply sustainability-relevant business data.

Separate the two security flows

Human IAM IdP → User → BTP Role Collection → RDP Role → Function
Machine IAM S/4 → Technical Identity → OAuth/API → RDP
This separation is useful during design workshops: a user-access issue and an interface-authentication issue are different security problems, even though both ultimately affect RDP.
03

BTP Authentication

Authentication answers: “Who are you?”

SAP documents that RDP uses the user-management and authentication mechanisms of SAP Business Technology Platform. In an enterprise environment, trust is commonly federated to SAP Cloud Identity Services or another corporate identity provider.

Traditional S/4 mental model

SU01 User → PFCG Role → Authorization Objects

BTP / RDP mental model

Identity Provider → BTP User → Role Collection → Application Role

Questions for a security workshop

  • Which IdP is authoritative for workforce users?
  • Is SAP Cloud Identity Services / IAS part of the trust chain?
  • How are users provisioned and deprovisioned?
  • Are BTP role collections assigned directly, by group mapping, or by another process?
  • Who can administer trust configuration?
  • What is the emergency-access process?

Do not treat a BTP role collection as technically identical to a PFCG role. It is a useful conceptual comparison, but BTP does not use the classic ABAP authorization-object model.

08

S/4HANA Integration

Understand what is replicated before designing security.

RDP uses replicated business data for reporting and analysis. SAP's learning content lists objects such as configuration data, organizational data, customers, products, deliveries, packaging elements, packaging compositions, material documents, suppliers, batches, and inventory.

S/4HANA / ECC
  • Configuration
  • Organizations
  • Products
  • Deliveries
  • Packaging
→
Integration Layer
  • Sustainability Data Integration
  • Push replication / APIs
  • File import where applicable
→
SAP RDP
  • EPR reporting
  • Packaging analysis
  • Compliance
For current S/4HANA integration, SAP also documents Sustainability Data Integration as a common integration capability for sustainability solutions. The exact pattern depends on source-system release, scope, and project design.

Important S/4 technical detail

SAP's current S/4HANA documentation describes integration scenarios that can involve OData services, BAdI implementation, OAuth, and RFC configuration. Packaging extraction may require customer-specific ABAP development depending on where packaging data is stored.

09

Integration Security

Review identity, transport, authorization, and data.

1

Authentication

Identify the technical identity used by the integration and how credentials or OAuth clients are governed.

2

Transport

Confirm HTTPS/TLS, certificate trust, endpoints, and secure destination configuration.

3

Authorization

Grant only the S/4 and BTP permissions required for the selected integration pattern.

4

Data Minimization

Review which business fields leave S/4 and ensure the interface does not transfer unnecessary sensitive data.

S/4-side review points

Potential areas depending on architecture: STRUST Certificate trust SM59 RFC / HTTP destination-related configuration OAuth Client / token configuration PFCG Least-privilege technical role OData Required services and authorizations ABAP/BAdI Customer-specific extraction logic
Do not create a technical PFCG role from assumptions. First establish the chosen integration pattern, exact services/APIs, extraction logic, technical identity, and required data objects.

11

Security Cheat Sheet

Questions to ask when a requirement arrives.

Human access?

Which identity, role collection, RDP roles, data scope and SoD rules apply?

System integration?

Which technical identity, protocol, endpoint, credentials and S/4 authorizations are required?

New role request?

Which persona owns the task? Can an existing role collection satisfy it?

New data feed?

What data leaves S/4, why is it required, and who can trigger or administer the replication?

Remember this: Human IAM: IdP → User → Role Collection → RDP Role Machine IAM: S/4 → Technical Identity → OAuth/API → RDP
